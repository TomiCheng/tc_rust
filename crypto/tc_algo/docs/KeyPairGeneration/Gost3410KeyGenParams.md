# Gost3410KeyGenParams

Enable the `gost3410` feature to use the `GOST3410` key pair generator of GOST R 34.10-94. Import
`Gost3410KeyGenParams` and `Gost3410Parameters` from `tc_algo::params::generate`, and the key types
from `tc_algo::params::key`.

The `GOST3410` row takes either of two params, as `DSA` does:

- a `Gost3410KeyGenParams`, to generate a new domain during `init`;
- a `Gost3410Parameters`, a domain already in hand, to make more pairs over it.

A `Gost3410Parameters` is both an input of the generator and part of each key, so
`tc_algo::params::key` exports it too. The two paths name the same type.

## Generate a key pair

```rust
use tc_algo::params::generate::{Gost3410KeyGenParams, Gost3410Parameters};
use tc_algo::params::key::{Gost3410PrivateKey, Gost3410PublicKey};
use tc_algo::{AlgoBuilder, AlgoError, DefaultAlgoBuilder};

fn main() -> Result<(), AlgoError> {
    let algo = DefaultAlgoBuilder::default().build();

    // A new domain of p of 1024 bits, then a pair over it
    let params = Gost3410KeyGenParams::new(1024);
    let pair = algo.key_pair_generator().generate_by_name_with("GOST3410", &params)?;

    let public = pair.public().as_any().downcast_ref::<Gost3410PublicKey>().expect("a Gost3410PublicKey");
    let private = pair.private().as_any().downcast_ref::<Gost3410PrivateKey>().expect("a Gost3410PrivateKey");
    assert_eq!(public.params(), private.params());

    // Each key carries the domain, which makes more pairs without generating it again
    let domain: &Gost3410Parameters = public.params();
    let other = algo.key_pair_generator().generate_by_name_with("GOST3410", domain)?;
    let other_public = other.public().as_any().downcast_ref::<Gost3410PublicKey>().expect("a Gost3410PublicKey");
    let other_private = other.private().as_any().downcast_ref::<Gost3410PrivateKey>().expect("a Gost3410PrivateKey");
    assert_eq!(other_public.params(), domain);
    assert_eq!(other_private.params(), domain);
    Ok(())
}
```

The generator returns a `KeyPair` whose `public()` is a `Gost3410PublicKey` and whose `private()`
is a `Gost3410PrivateKey`, each inside `Box<dyn Params>` and each holding a copy of the domain. The
domain and the keys draw from the source of `DefaultAlgoBuilder::set_rand`.

`GOST3410` has no default, so `generate_by_name("GOST3410")` returns `NotInitialized`. Any params
other than these two are `InvalidParams`.

GOST R 34.10-94 is withdrawn; it is here for old data. Its successors are over elliptic curves,
the `ECGOST3410` rows of [EC](../Ec.md).

## Settings

| Method | Setting | Default | Valid range |
|---|---|---|---|
| `new(size)` | Bits of `p` | none | 512 or 1024 |

The domain is generated by procedure 2 of the standard's annex A, Bouncy Castle's default, with
`q` of 256 bits. Nothing is checked when the params are built; `init` generates the domain, and
returns `InvalidParams` for another size. Generating a domain takes a while, so `init` once and
`generate` as many pairs as needed, or keep the domain and pass it as a `Gost3410Parameters`.

| Accessor | Returns |
|---|---|
| `size()` | Bits of `p` (`u32`) |

## A domain in hand

A `Gost3410Parameters` comes from a key, as `public.params()` gives it, or from elsewhere with
`Gost3410Parameters::new(p, q, a)`. The numbers are `PaddedBigUint` of `tc_bigint`, which
`tc_algo` does not re-export. A domain is not checked when it is built, nor at `init`; `generate`
checks that `p` and `q` are odd and above 2, `q` is below `p` and `a` is in `[2, p - 1]`, and
returns `InvalidParams` otherwise. Whether `p` and `q` are prime is not checked, so a domain from
an untrusted source is up to the caller.

The named domains of CryptoPro (RFC 4357), Bouncy Castle's `Gost3410NamedParameters`, are not
here yet.

| Accessor | Returns |
|---|---|
| `p()` | Modulus (`&PaddedBigUint`) |
| `q()` | Order of the subgroup (`&PaddedBigUint`) |
| `a()` | Generator (`&PaddedBigUint`) |
| `validation()` | The `x0` and `c` the domain was generated from (`Option<&Gost3410ValidationParameters>`) |
