# GOST R 34.10-94

GOST R 34.10-94 is the Russian signature of 1994, a DSA-like scheme over a prime field, signed over
the hash of GOST R 34.11-94. Its successors, GOST R 34.10-2001 and -2012, are over elliptic curves:
they are the `ECGOST3410` rows of [EC](Ec.md#signing).

The `gost3410` feature of `tc_algo` has the rows. GOST R 34.10-94 is withdrawn; it is here for old
data.

## Key pairs

A new domain and a pair over it:

```rust
use tc_algo::params::generate::Gost3410KeyGenParams;
use tc_algo::{AlgoBuilder, AlgoError, DefaultAlgoBuilder};

fn main() -> Result<(), AlgoError> {
    let algo = DefaultAlgoBuilder::default().build();

    // A new domain of p of 1024 bits, then a pair over it
    let params = Gost3410KeyGenParams::new(1024);
    let pair = algo.key_pair_generator().generate_by_name_with("GOST3410", &params)?;

    let (_public, _private) = pair.into_parts();
    Ok(())
}
```

### Algorithms

| Name | Aliases | OID | Feature | Params | Public key | Private key |
|---|---|---|---|---|---|---|
| `GOST3410` | `GOST-3410`, `GOST-3410-94` |  | `gost3410` | `Gost3410KeyGenParams`, `Gost3410Parameters` | `Gost3410PublicKey` | `Gost3410PrivateKey` |

The name and aliases are those of Bouncy Castle's `GeneratorUtilities`, and their case does not
matter.

### Params

- `Gost3410KeyGenParams::new(size)` generates a new domain at `init` by procedure 2 of the
  standard's annex A, Bouncy Castle's default, with p of 512 or 1024 bits.
- A `Gost3410Parameters`, the domain of another key, makes more pairs over the same domain.

Any other type is `InvalidParams`.
[Gost3410KeyGenParams](KeyPairGeneration/Gost3410KeyGenParams.md) lists the settings, the checks
and the [CryptoPro named domains](KeyPairGeneration/Gost3410KeyGenParams.md#named-domains).

## Signing

From a new pair to a verified signature:

```rust
use tc_algo::params::generate::Gost3410KeyGenParams;
use tc_algo::{AlgoBuilder, AlgoError, DefaultAlgoBuilder};

fn main() -> Result<(), AlgoError> {
    let algo = DefaultAlgoBuilder::default().build();
    let name = "GOST3410";
    let message = b"attack at dawn";

    // Generate a pair
    let params = Gost3410KeyGenParams::new(1024);
    let pair = algo.key_pair_generator().generate_by_name_with("GOST3410", &params)?;

    // Sign with the private key
    let mut signer = algo.signer().get_by_name(name)?;
    signer.init(pair.private())?;
    signer.update(message)?;
    let signature = signer.sign()?;

    // Verify with the public key
    let mut verifier = algo.signer().get_by_name(name)?;
    verifier.init(pair.public())?;
    verifier.update(message)?;
    assert!(verifier.verify_signature(&signature)?);

    Ok(())
}
```

### Algorithms

| Name | Aliases | OID | Feature |
|---|---|---|---|
| `GOST3410` | `GOST-3410`, `GOST-3410-94`, `GOST3411WITHGOST3410`, `GOST3411/GOST3410` | `1.2.643.2.2.4` | `gost3410` |

The names and OID are those of Bouncy Castle's `SignerUtilities`, and the case of a name does not
matter. The digest is GOST R 34.11-94, the scheme's own, so the row needs no digest feature.

### Params

The row takes a `Gost3410PrivateKey` to sign and a `Gost3410PublicKey` to verify, and any other
type is `InvalidParams`.

### Using it

- k is drawn at random for each signature, from the source of `DefaultAlgoBuilder::set_rand`.
- The rest is common to every signer: [Signers](Signer.md#using-it).
