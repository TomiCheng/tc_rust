# X25519 and X448

X25519 and X448, RFC 7748, agree on a secret over the Montgomery curves curve25519 and curve448.
Each side's private key is 32 or 56 random bytes, its public key as many bytes, and the shared
secret is as long again. They are the Diffie-Hellman of these curves, not signatures: for those,
[EdDSA](EdDSA.md) runs over the same curves in another form, with keys of its own.

The `cfrg-curves` feature of `tc_algo` has the rows of X25519 and X448.

## Key pairs

A new pair needs no params:

```rust
use tc_algo::{AlgoBuilder, AlgoError, DefaultAlgoBuilder};

fn main() -> Result<(), AlgoError> {
    let algo = DefaultAlgoBuilder::default().build();

    let pair = algo.key_pair_generator().generate_by_name("X25519")?;

    // The public key goes to the other side; the private key stays here
    let (_public, _private) = pair.into_parts();
    Ok(())
}
```

### Algorithms

| Name | OID | Feature | Params | Public key | Private key |
|---|---|---|---|---|---|
| `X25519` | `1.3.101.110` | `cfrg-curves` | none | `X25519PublicKey` | `X25519PrivateKey` |
| `X448` | `1.3.101.111` | `cfrg-curves` | none | `X448PublicKey` | `X448PrivateKey` |

The names and OIDs are those of Bouncy Castle's `GeneratorUtilities`, and the case of a name does
not matter.

### Params

None: `generate_by_name` generates a pair, and `init` refuses any params as `InvalidParams`.
`X25519PrivateKey::new` and `X25519PublicKey::new` make keys of bytes from elsewhere, as a public
key read from a peer, and `generate_public_key` gives the public key of a private one. The keys are
in `tc_algo::params`.

## Agreement

From two new pairs to one shared secret:

```rust
use tc_algo::{AlgoBuilder, AlgoError, DefaultAlgoBuilder};

fn main() -> Result<(), AlgoError> {
    let algo = DefaultAlgoBuilder::default().build();

    // Generate a pair for each side
    let alice = algo.key_pair_generator().generate_by_name("X25519")?;
    let bob = algo.key_pair_generator().generate_by_name("X25519")?;

    // Alice's private key with Bob's public key
    let mut agreement = algo.agreement().get_by_name("X25519")?;
    agreement.init(alice.private())?;
    let mut alice_secret = vec![0; agreement.agreement_size()];
    agreement.calculate_agreement(bob.public(), &mut alice_secret)?;

    // Bob's private key with Alice's public key gives the same secret
    let mut agreement = algo.agreement().get_by_name("X25519")?;
    agreement.init(bob.private())?;
    let mut bob_secret = vec![0; agreement.agreement_size()];
    agreement.calculate_agreement(alice.public(), &mut bob_secret)?;

    assert_eq!(alice_secret, bob_secret);
    Ok(())
}
```

### Algorithms

| Name | OID | Feature | Params | Other side's key | Secret bytes |
|---|---|---|---|---|---|
| `X25519` | `1.3.101.110` | `cfrg-curves` | `X25519PrivateKey` | `X25519PublicKey` | 32 |
| `X448` | `1.3.101.111` | `cfrg-curves` | `X448PrivateKey` | `X448PublicKey` | 56 |

The names and OIDs are those of Bouncy Castle's `AgreementUtilities`. Any other type of key is
`InvalidParams`.

### Using it

- `get_by_name` and `get_by_oid` give an `Agreement` of `tc_agreement`, as every agreement row does;
  see [Agreement](Agreement.md).
- **The secret is not yet a key.** Put it through a KDF, such as HKDF, before using it.
- **It does not say who is on the other side.** Authenticate the public keys, for instance with a
  certificate or a signature.
- `agreement_size` is 32 or 56 from the start, since the curve is fixed. A shorter buffer is
  `DataLength`.
- A public key of small order gives a secret of all zeros, which is refused as `InvalidParams`, as
  RFC 7748 allows and Bouncy Castle does.
- It gives `NotInitialized` before an `init` that succeeded.
- The scalar multiplication is constant time with respect to the private key.
