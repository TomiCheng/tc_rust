# X448

X448 is Diffie-Hellman on Curve448, of RFC 7748: each party makes a key pair,
they swap public keys, and each combines its own private key with the other's public
key. Both get the same 56-byte secret; someone who saw only the public keys does not.
Unlike finite-field DH there is no group to agree on: the curve is fixed. It works as
X25519 does, at about 224 bits of security rather than 128.

In `tc_algo_old` this takes two factories: `algo.key_pair_generator()` makes the key pairs and
`algo.agreement()` calculates the secret, after Bouncy Castle's `GeneratorUtilities` and
`AgreementUtilities`. Both know X448 by the name `"X448"` and by its OID,
1.3.101.111.

## Enabling X448

X448 comes with the `x448` feature. The keys
come from `tc_cfrg_curves`; add it, at the version `tc_algo_old` uses, only to make a
key from bytes, such as the public key the other party sends.

```toml
[dependencies]
tc_algo_old = { version = "0.1", features = ["x448"] }
tc_cfrg_curves = "0.1" # only to make keys from bytes
```

## Usage

### Both parties, step by step

```rust
use tc_algo_old::{Algo, AlgoError};

fn main() -> Result<(), AlgoError> {
    let algo = Algo::new();
    // 1. Each party makes a key pair and sends the public key to the other
    let alice = algo.key_pair_generator().generate("X448")?;
    let bob = algo.key_pair_generator().generate("X448")?;

    // 2. Alice combines her private key with Bob's public key ...
    let mut agreement = algo.agreement().get_by_name("X448")?;
    agreement.init(&alice.private.into())?;
    let alice_secret = agreement.calculate(&bob.public.into())?;

    // ... and Bob combines his with Alice's, for the same secret
    let mut agreement = algo.agreement().get_by_name("X448")?;
    agreement.init(&bob.private.into())?;
    let bob_secret = agreement.calculate(&alice.public.into())?;

    assert_eq!(alice_secret.as_bytes(), bob_secret.as_bytes());
    Ok(())
}
```

`init` takes this party's private key in an `AnyAgreementParams`, and `calculate`
takes the other party's public key in an `AgreementPeer`. `.into()` makes either from
the key alone: the params from an `AnyPrivateKey`, the peer from an `AnyPublicKey`.
One agreement calculates as many secrets as you like with the key it was initialized
with.

### In one step

`algo.agreement().calculate` finds the agreement, initializes it and calculates.

```rust
use tc_algo_old::{Algo, AlgoError};

fn main() -> Result<(), AlgoError> {
    let algo = Algo::new();
    let alice = algo.key_pair_generator().generate("X448")?;
    let bob = algo.key_pair_generator().generate("X448")?;

    let secret = algo.agreement().calculate("X448", &alice.private.into(), &bob.public.into())?;
    Ok(())
}
```

### Sending and receiving a public key

An X448 public key is 56 bytes, the u-coordinate of RFC 7748, and protocols such as
TLS 1.3 and SSH send those bytes as they are. `u()` gives them and
`X448PublicKey::new` makes a key of them again.

```rust
use tc_algo_old::{Algo, AlgoError, AnyPublicKey};
use tc_cfrg_curves::X448PublicKey;

// To send: the 56 bytes of a public key
fn to_bytes(public: &AnyPublicKey) -> [u8; 56] {
    let AnyPublicKey::X448(key) = public else {
        panic!("not an X448 key");
    };
    *key.u()
}

// On receipt: the other party's 56 bytes, as a public key
fn from_bytes(bytes: [u8; 56]) -> AnyPublicKey {
    AnyPublicKey::X448(X448PublicKey::new(bytes))
}

fn main() -> Result<(), AlgoError> {
    let algo = Algo::new();
    let mine = algo.key_pair_generator().generate("X448")?;
    let sent = to_bytes(&mine.public);

    // What the other party sent
    let received = to_bytes(&algo.key_pair_generator().generate("X448")?.public);

    let theirs = from_bytes(received);
    let secret = algo.agreement().calculate("X448", &mine.private.into(), &theirs.into())?;
    Ok(())
}
```

Any 56 bytes make a public key; `calculate` refuses one that would give a secret of
all zeros.

### The secret is not yet a key

The secret is 56 bytes, a u-coordinate as well. Its bytes are not uniformly random, so
do not use them as a key: derive the key from them with a KDF, such as HKDF, and give
the KDF what both parties agree to bind the key to, as TLS 1.3 does with the
handshake, both public keys included.

So the secret is a `SharedSecret`, not a `SecretKey`, and cannot go to a cipher as
it is. `as_bytes` gives its bytes to the KDF, and they are wiped when it is dropped.
It cannot be cloned, which keeps one copy of it, nor compared with `==`, which would
take time that depends on its bytes.

### Into a buffer of your own

`AnyAgreement` also implements the `Agreement` and `AgreementInit` traits, which
`tc_algo_old` re-exports, so it fits generic code. `calculate_agreement`
writes the secret into the first `agreement_size` bytes of a buffer, 56 for X448.

```rust
use tc_algo_old::{Agreement, Algo, AlgoError};

fn main() -> Result<(), AlgoError> {
    let algo = Algo::new();
    let alice = algo.key_pair_generator().generate("X448")?;
    let bob = algo.key_pair_generator().generate("X448")?;

    let mut agreement = algo.agreement().get_by_name("X448")?;
    agreement.init(&alice.private.into())?;
    let mut secret = [0; 56];
    agreement.calculate_agreement(&bob.public.into(), &mut secret)?;
    Ok(())
}
```

`agreement_size` panics before a successful `init`; `calculate` returns
`NotInitialized` instead.

### When it fails

Every error is an `AlgoError`; its `kind` says what went wrong, and `source` gives
the error of the X448 layer underneath, where there is one.

| `ErrorKind` | When |
|---|---|
| `UnknownAgreement` | The name is not X448 or 1.3.101.111, or the `x448` feature is off |
| `UnknownGenerator` | Likewise for the generator |
| `InvalidKeyGenParams` | The generator's `init` with a size other than 448 bits |
| `InvalidParams` | `init` with a key that is not X448, with an ephemeral key, or with user keying material. `calculate` with an ephemeral key, a public key that is not X448, or one of small order, whose secret is all zeros |
| `NotInitialized` | `calculate` before a successful `init` |
| `DataLength` | `calculate_agreement` with a buffer shorter than 56 bytes |

```rust
use tc_algo_old::{Algo, AlgoError, AnyPublicKey, ErrorKind};
use tc_cfrg_curves::X448PublicKey;

fn main() -> Result<(), AlgoError> {
    let algo = Algo::new();
    let mine = algo.key_pair_generator().generate("X448")?;

    // u = 0 has small order
    let zero = AnyPublicKey::X448(X448PublicKey::new([0; 56]));

    let error = algo.agreement().calculate("X448", &mine.private.into(), &zero.into())
        .unwrap_err();
    assert_eq!(error.kind(), ErrorKind::InvalidParams);
    Ok(())
}
```

## Names

| Name | Aliases | OID | Feature |
|---|---|---|---|
| X448 | | 1.3.101.111 (id-X448) | `x448` |

Names match without regard to ASCII case, and the dotted OID works wherever a name
does. Both factories know the same name and OID, that of RFC 8410, as in Bouncy
Castle. Bouncy Castle gives X448 from `GetRawAgreement`, apart from `DH` and the
other agreements of `GetBasicAgreement`; here all are in one table.

## Notes

- **The public key is not checked beforehand**: RFC 7748 takes any 56 bytes; unlike
  X25519, no bit is ignored, as 448 bits fill the bytes. What `calculate` refuses is a
  secret of all zeros, which is what a public key of small order gives, as RFC 7748
  recommends.
- **The generator makes 448 bits**, the only size of X448; `init` takes
  `KeyGenParams::Strength { bits: 448 }`, Bouncy Castle's strength for it, and
  nothing else. Without `init` it makes the same.
- **A private key is any 56 bytes**: the scalar is clamped as RFC 7748 says each time
  it is used, so keys made elsewhere need not be clamped first.
- **Timing**: the scalar multiplication takes time that does not depend on the
  private key. The check for a secret of all zeros shows only whether it is all
  zeros, which the error shows anyway.
- **Forward secrecy** comes from making a new key pair for each exchange and dropping
  it afterwards. A key pair kept for months makes every secret it took part in
  readable to whoever later takes the private key.
- **No key is printed**: the `Debug` output of an `AnyPrivateKey`, an agreement or a
  `SharedSecret` shows the algorithm or the length, never the key or the secret. A
  public key shows its bytes, which are public.
